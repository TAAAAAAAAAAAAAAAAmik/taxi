2026-07-03 (Claude) — рефералка / оплата бонусами
- Кошелёк на ledger: FIFO-погашение обязано идти до проверки expiry, иначе истечение старого кредита «воскрешает» уже потраченные бонусы. Порядок: сортировка кредитов по createdAt → гашение долга → остаток учитывается только если не истёк.
- Дедуп начислений по (userId, sourceType, sourceId) без текста причины — иначе авто-начисление и админское подтверждение с разными reason создают двойную выплату.
- Тумблер бонусов встал внутрь существующего orderPriceCard как третья строка (чекбокс 18px + текст), а не отдельной карточкой: ценник остаётся единственным местом правды о цене, CTA пересчитывается тем же bonusDiscount.
- Для QA статического билда на localhost демо-режим включается через page.addInitScript с globalThis.process.env.EXPO_PUBLIC_ENABLE_DEMO='true' — getPublicEnv читает runtime-process раньше вшитого env.

2026-07-04 (Claude) — кино-запуск и motion заказа
- Белую вспышку web-старта убирает только статичный splash в самом index.html (JS-бандл грузится слишком поздно). Инъекция пост-экспортным скриптом, а не правкой шаблона expo, — переживает любой ре-экспорт.
- Ключ бесшовности: boot-splash (HTML) и React-splash и Welcome-hero живут в ОДНОМ мире (графит #0A1411 + лайм). Тогда стыки между тремя слоями невидимы — глазу не за что зацепиться.
- React-splash кладём слоем ПОВЕРХ навигатора (absolute fill, zIndex), а не через тернарник вместо него: приложение монтируется под сплэшем и к моменту его ухода уже готово — переход мгновенный.
- Одометр чисел (TickerText): при серии быстрых изменений не копим очередь анимаций — гасим старое (90мс), показываем последний target, поднимаем новое (180мс). Флаг animating.current защищает от наложения.
- CTA-морф стрелка→спиннер во время сабмита читается как «система работает», а не «кнопка зависла» — дешёвый способ снять тревогу ожидания.

2026-07-07 · Регистрация в премиум-язык
- Онбординговый многошаговый флоу заиграл от одного приёма: тёмный hero с
  лаймовой прогресс-линией + чипы шагов. На 390px пять чипов с подписями не
  влезают — подпись оставлять только у активного, done показывать ✓.
- Активная роль-карточка глубоким зелёным (#0B7C48) с лаймовым чеком читается
  сильнее, чем рамка; фирменный рельс маршрута (точка→линия→пин) — дешёвый
  способ добавить бренд в любую карточку.
- Дубли навигации (вертикальный список шагов + hero-прогресс) убирать сразу:
  один источник прогресса.

2026-07-07 · Пошаговая валидация регистрации
- «Продолжить» с блокировкой по ошибкам ТЕКУЩЕГО шага + инлайн-подсветка полей
  ощутимо удобнее финального списка ошибок. Красное включать только после
  попытки продолжить и гасить на первом же исправлении символа.
- С финального шага давать чипы «Исправить: <Шаг>» — переход сразу
  с подсвеченными полями, а не заставлять искать.
- Валидацию держать по-полевой (id → сообщение); плоский список для сводки
  собирать из неё же — одна формулировка везде.
