# Протокол команды Claude + Codex

Этот файл — единый регламент совместной работы двух агентов.
- Codex читает свою инструкцию в `AGENTS.md`.
- Claude читает свою инструкцию в `CLAUDE.md`.
- Роли Codex (Frontend / Backend / QA / Product) — в `17_codex_roles.md`.
- Этот файл описывает, **как они передают работу друг другу**.

## Принцип

Один «мозг», две пары рук. Codex — скорость и объём, Claude — целостность и вкус.

> Codex набрасывает черновик и инфраструктуру → Claude доводит архитектуру, бизнес-логику и дизайн → оба перекрёстно ревьюят.

## В чём каждый сильнее (зоны по умолчанию)

| Зона | Кто ведёт |
|---|---|
| Черновик с нуля, каркас экрана | Codex |
| Инфраструктура: `scripts/`, конфиги, билд, eas, smoke-тесты | Codex |
| Повторяющиеся механические правки | Codex |
| Архитектура, рефакторинг, конвенции `src/` | Claude |
| Бизнес-логика, статусы заказа, гонки, идемпотентность, биллинг | Claude |
| Дизайн, UI/UX, тексты интерфейса | Claude |
| Код-ревью и ловля тонких багов | Claude (+ Codex как второй движок) |

Граница не жёсткая. Если задача мелкая и целиком в одной зоне — её делает один агент целиком, без передачи.

## Поток работы на одну фичу

1. **Постановка.** Задача кладётся в `10_current_task.md` (узко, по правилам `12_codex_limit_saving.md`).
2. **Черновик (Codex).** Codex набрасывает каркас / инфраструктуру: `codex exec "<узкий промпт>"`. Отчитывается, какие файлы тронул, и дописывает `codex_learning_log.txt`.
3. **Доводка (Claude).** Claude принимает черновик: чинит архитектуру, бизнес-логику, дизайн/UX. Прогоняет нужные навыки (`rn-code-quality`, `taxi-backend-reliability`, `taxi-visual-qa`).
4. **Перекрёстное ревью.** Финальную вычитку делает второй движок: `codex exec review` ⇄ Claude `/code-review`. Два движка ловят разные баги.
5. **Проверка сборки.** `npm run typecheck` должен остаться зелёным (или не хуже, чем был). Профильные smoke-тесты по теме.
6. **Фиксация.** Обновить `09_last_state.md`; каждый дописывает свой learning-log.

## Как передавать (механика)

- **Claude → Codex** (отдать механику/черновик): `codex exec "<промпт>"`; для ревью — `codex exec review`.
- **Codex → Claude** (подхватить): состояние читается из `09_last_state.md`, `10_current_task.md` и логов — Claude продолжает оттуда.
- Длинные ТЗ не вставлять в чат — хранить в `project-brain/*.md` и указывать, какие файлы читать.

## Консультации Claude ↔ Codex (второе мнение)

Claude может не только делегировать, но и **советоваться** с Codex по важным вопросам — это полноценный диалог с продолжением треда.

Когда консультироваться: архитектурные развилки, надёжность (гонки, идемпотентность, статусы), модель данных, рискованный рефактор, второе мнение по тонкому багу. НЕ ради мелочей — каждый вызов тратит лимиты Codex (`12_codex_limit_saving.md`).

Как (проверенные команды, read-only — Codex ничего не меняет):

```bash
# первый вопрос (создаёт тред)
codex exec --sandbox read-only --skip-git-repo-check -o ~/.codex_consult.txt "<важный вопрос, кратко, на русском>"

# продолжить тот же тред (у resume нет -s, режим задаём через -c)
codex exec resume --last --skip-git-repo-check -c sandbox_mode="read-only" -o ~/.codex_consult.txt "<уточнение/возражение>"
```

Правила консультации:
- Вопрос узкий, с просьбой «не сканировать весь проект» — экономит лимиты.
- Решение всё равно принимает Claude (синтез двух мнений), а не «как сказал Codex».
- Если консультация привела к решению — фиксировать его в `06_project_decisions.md` (и `09_last_state.md`), а не только в чате.

## Правила, общие для обоих

- Одна маленькая задача за раз: анализ → код → проверка → следующая.
- Не переписывать проект с нуля, не ломать сборку, не раздувать MVP.
- Приоритет — главный MVP-сценарий заказа.
- Дизайн не копирует Uber / Yandex Go; держим премиальную локальность.
- Общение с пользователем — на русском.

## Параллельная работа без коллизий

Когда Claude и Codex работают одновременно (разные чаты/сессии), главный риск — оба правят один файл и затирают работу друг друга. Особенно без git.

Правила:
- Делить по **файлам**, не только по темам. Один файл в один момент времени правит только один агент.
- Пока Claude занят надёжностью бэка и бизнес-логикой (`scripts/mvp-backend.mjs`, `src/services`, `src/state`, бизнес-`src/screens`) и дизайном — Codex берёт **другие** файлы.
- Безопасные параллельные зоны для Codex: smoke-тесты (`scripts/*-smoke-test.mjs`), инфраструктура (`.gitignore`, eas/pilot/release-скрипты, валидация env, импорт справочников), изолированные утилиты, которые Claude сейчас не трогает.
- «Кто что держит прямо сейчас» объявлять в `10_current_task.md` одной строкой: какой агент в каких файлах.
- Узкая задача за раз — не «улучшай проект», а конкретный файл/набор.
- Без git коллизия = потерянная работа, поэтому `git init` желателен до активной параллельной работы.

## Кто принимает спорное

- Архитектурный / продуктовый / дизайнерский спор → решает Claude.
- Спор про инфраструктуру / сборку / производительность грубой механики → решает Codex.
- Если расходятся по факту (баг есть / бага нет) → правда у того, кто воспроизвёл на реальном запуске.
