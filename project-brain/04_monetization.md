# Монетизация

## Главная модель заработка

Проект зарабатывает на водителях, которые получают доступ к заказам.

## Вариант 1 — подписка

Водитель платит фиксированную сумму в месяц и получает доступ к заказам.

Пример:
- 3000 рублей в месяц;
- без комиссии с каждого заказа;
- водитель забирает оплату за поездку себе.

Плюс:
водителю понятно, сколько он платит.

## Вариант 2 — процент с заказа

Водитель не платит подписку, но отдаёт процент с каждого заказа.

Пример:
- 7% с заказа.

Плюс:
водителю легче начать, потому что не нужно платить заранее.

## Как реально движутся деньги (уточнено владельцем, 2026-06-15)

- Клиент платит за поездку **напрямую таксисту** (на счёт водителя), а не через платформу. В системе «оплата заказа» (`/orders/:id/payment`) — это запись клиент↔водитель, а не списание через платформу.
- Таксист платит платформе (владельцу) одним из двух способов на выбор:
  - **Партнёр PRO (подписка)** — фиксированная сумма раз в **месяц**, без процента с заказов;
  - **Комиссия** — процент с заказов, который водитель отдаёт владельцу **каждый день**.
- Перевод доли владельцу — это поток `service-share` в backend (статусы `pending_transfer → reported_transferred → confirmed`).

Следствия для разработки:
- Идемпотентность критична для **перевода доли водителя и оплаты подписки**, а не для платежей клиента (их через платформу нет).
- Суммы, комиссии и доли считать в целых копейках (integer), не во float.

## Что важно

На раннем этапе не нужно сразу подключать реальные платежи.

Сначала:
1. сделать экран тарифов;
2. сделать выбор модели работы;
3. сделать статус доступа водителя;
4. сделать ручное подтверждение оплаты админом.

Реальные платежи подключать только после стабильного MVP.
