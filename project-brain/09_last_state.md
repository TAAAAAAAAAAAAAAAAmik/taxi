## 2026-06-18 (Codex) — Фаза 0/1/2 по плану Claude

- Проверено: `npm run typecheck`, `npm run test:driver-billing`, `npm run test:registration-no-sms` — зелёные. Expo web поднят локально на `http://localhost:19006`.

## 2026-06-15 (Claude) — идемпотентность принятия заказа + аудит статус-переходов

- Аудит: forward-only валидация статусов и защита от гонки двух водителей УЖЕ реализованы (`ORDER_STATUS_RANK` + `isAllowedOrderStatusTransition`; accept под сериализованным `mutateDb` с проверкой `order.driver?.id` и `['created','searching']`). Долг из прошлой версии этого файла устарел — внедрять заново было нечего (подтверждено записью в `07_bugs.md`).
- Фикс: повторное «принять» тем же водителем теперь no-op `200` вместо вводящего в заблуждение `409` (`mvp-backend.mjs`, обработчик `assign`). Биллинг на повторный `completed` идемпотентен (`settleOrderPayment` пересчитывает дневную долю, не инкрементирует) — отдельной правки не понадобилось.
- Решение записано в `06_project_decisions.md` (п.10), баг — в `07_bugs.md`. Проверено: `npm run test:dispatch`, `test:realtime` — зелёные.
- Процесс: решение принято после read-only консультации с Codex (диалог в треде), но адаптировано под реальные статусы проекта, а не под его generic-таблицу `new/accepted/in_progress`.
