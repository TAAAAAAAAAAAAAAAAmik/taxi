# Design Rules

## Главная цель дизайна

Приложение должно быть удобным, понятным и приятным на телефоне.

## Общие правила

- Кнопки должны быть крупными
- Текст должен быть читабельным
- Контраст должен быть нормальным
- Нельзя делать белый текст на светлом фоне
- Нельзя делать слишком мелкий шрифт
- Главные действия должны быть видны сразу
- Экран не должен быть перегружен
- Пользователь должен понимать, куда нажимать

## Стиль бренда

Kinetix / Такси Партнер должен ощущаться как:

- локальный
- надежный
- быстрый
- современный
- простой
- без лишнего пафоса

## Для клиента

Клиент должен быстро понять:

1. как заказать машину;
2. куда ввести адрес;
3. сколько примерно будет стоить поездка;
4. какой статус у заказа.

## Для водителя

Водитель должен быстро понять:

1. какие заказы доступны;
2. какой заказ он принял;
3. какой у него статус;
4. сколько он заработал;
5. активен ли его доступ к системе.

# Премиальная локальность

Локальность приложения не должна выглядеть колхозно.

Если задача связана с дизайном, текстами, главным экраном, экраном заказа или позиционированием, Codex должен читать:

- project-brain/18_design_benchmark_yandex_uber.md
- project-brain/19_unique_product_identity.md
- project-brain/20_premium_local_identity.md

Главное правило:

делать не "сельское такси", а современный локальный сервис.

Локальность показывать через пользу:
- быстрые маршруты;
- знакомые направления;
- понятные условия;
- локальную поддержку;
- удобство для района.

Не показывать локальность через дешевые визуальные клише.
