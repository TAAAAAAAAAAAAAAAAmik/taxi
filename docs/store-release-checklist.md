# Чек-лист APK и будущей публикации

## Цель текущего среза

Первый закрытый rehearsal-пилот распространяется как Android APK среди ограниченного круга участников. Google Play, App Store, TestFlight, прием платежей, production backend с HTTPS и публичные домены не входят в этот срез.

## Android APK для пилота

- Использовать профиль EAS `pilot-apk`.
- Перед сборкой выполнить `npm run prepare:pilot-apk`, чтобы `EXPO_PUBLIC_API_URL` в `eas.json` получил LAN-адрес компьютера с backend.
- Держать `EXPO_PUBLIC_APP_ENV=pilot`.
- Держать `EXPO_PUBLIC_ENABLE_DEMO=false`, чтобы скрыть demo-входы и demo-админку.
- Для пилота без SMS держать `EXPO_PUBLIC_SKIP_PHONE_VERIFICATION=true` в APK и `MVP_SKIP_PHONE_VERIFICATION=true` на backend.
- Проверить, что телефон с APK и backend находятся в одной сети.
- Проверить `/health` backend с телефона до начала пилота.
- Не передавать APK за пределы списка участников пилота.

Команды:

```bash
npm run backend:pilot
npm run prepare:pilot-apk
npm run build:pilot-apk
```

## Минимум перед раздачей APK

- Пользовательское соглашение, политика конфиденциальности и согласие на персональные данные подготовлены как черновики для юриста.
- В `docs/legal/source-benchmark.md` зафиксированы внешние ориентиры, но тексты не копируют документы сторонних сервисов.
- В приложении есть удаление аккаунта или понятный путь через поддержку.
- Регистрация без SMS включена только для закрытого пилота и запрещена для production.
- Поддержка отвечает по заказам, документам, безопасности и доступу.
- Водитель не получает заказы без документов, правового допуска и ручной активации доступа.
- Документы водителя включают паспорт, ВУ, СТС, ОСАГО и ОСГОП.
- Администратор может заблокировать водителя и отключить доступ.
- В пилоте не обещается гарантированный доход или гарантированный поток заказов.
- В пилоте нет списаний через приложение; будущая модель доступа раскрыта как 3000 руб. за 30 дней без комиссии или 7% с поездки без ежемесячного платежа.

## Что остается для Google Play

- Заполнить Data safety form.
- Указать, какие данные собираются, зачем они нужны и передаются ли третьим лицам.
- Проверить удаление аккаунта и данных по требованиям Google Play.
- Подключить Android App Links через `assetlinks.json` на рабочем HTTPS-домене.
- Не включать опасные разрешения Android до появления реальной функции.
- Подготовить реальное название приложения, описание, скриншоты, категорию и возрастной рейтинг.

## Что остается для App Store

- Подготовить Apple Developer account и TestFlight.
- Добавить ссылку на privacy policy.
- Проверить удаление аккаунта, если регистрация остается включенной.
- Запрашивать разрешения iOS только в момент использования функции.
- Подключить Universal Links через `apple-app-site-association` на рабочем HTTPS-домене.

## Инвайт-ссылки

Текущая заготовка:

- iOS: `associatedDomains` в `app.config.js` берется из `EXPO_PUBLIC_LINKS_DOMAIN`.
- Android: `intentFilters` в `app.config.js` берется из `EXPO_PUBLIC_LINKS_DOMAIN`.
- Рабочий домен: задается через `EXPO_PUBLIC_LINKS_DOMAIN` / `MVP_LINKS_ORIGIN`.

Для APK-пилота deep links можно проверять позже. Перед публикацией в сторах домен должен обслуживать `apple-app-site-association` и `assetlinks.json`.

## Документы и фото

Для закрытого пилота уже используется экран загрузки документов и backend private storage. Перед production нужно отдельно утвердить:

- шифрование передачи на сервер через HTTPS;
- private object storage вместо локальной папки;
- ограниченный доступ сотрудников к документам;
- сроки хранения и процедуру удаления;
- отдельные тексты согласий для водительских документов.
